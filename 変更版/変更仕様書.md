# Streamlit UI・SQLite拡張 変更仕様書

## 1. 目的

現在のスケジューリング処理を活用し、Streamlit上で以下を実行できるようにする。

- 乱数シードを指定したダミーデータ生成
- ダミーデータの確認
- 製品選択方式、優先度方式、オーバーラップ設定の切り替え
- 停止時間・ブロック時間の変更
- 通常探索によるスケジューリング実行
- スケジュール結果およびガントチャートの確認
- 実行結果のSQLite保存

## 2. 作業場所に関する方針

以降のStreamlit、SQLite、UI、可視化、データ変換、検証に関する変更作業は、原則としてこの`変更版`ディレクトリ内で行う。

既存コードは、必要な場合を除いて直接変更しない。既存アルゴリズムを利用する場合も、変更版側から呼び出す構成を優先する。

## 3. 対象外

初期実装では以下を対象外とする。

- タブーサーチなど通常探索以外のアルゴリズム
- ダミーデータ本体の直接編集
- 工場数を利用したスケジューリング
- 既存の評価指標の大幅な変更

## 4. データベース

データベースにはSQLiteを使用する。

保存対象は以下とする。

- ダミーデータ生成条件
- 受注データ
- 製品データ
- 工程データ
- 停止時間
- 段取ブロック時間
- 加工ブロック時間
- スケジューリング実行履歴
- スケジュール結果
- 評価結果
- 制約検証結果

同一の乱数シードと同一条件から、同じダミーデータを再生成できるようにする。

## 5. ダミーデータ生成

画面から以下の条件を指定できるようにする。

- 乱数シード
- 受注数
- 製品数
- 製品選択方式
- 優先度方式
- オーバーラップ設定

「ダミーデータをリセット」操作により、指定条件でダミーデータを再生成し、SQLiteへ保存する。

ダミーデータ本体は読み取り専用とし、受注、製品、工程の各データを直接編集する機能は設けない。

## 6. 工場数の扱い

工場数は現在のスケジューリング処理で使用していないため、以下の扱いとする。

- Streamlitの入力項目には表示しない
- ダミーデータ確認画面には表示しない
- 新しいUI用データには含めない
- 既存の`Factory.seed`および`Factory.count`は、将来利用の可能性があるため削除しない

## 7. 切り替え項目

### 7.1 製品選択方式

- 連続
- ランダム

### 7.2 優先度方式

- 連続
- ランダム

### 7.3 オーバーラップ

- 有効
- 無効

設定変更後は自動反映せず、「ダミーデータをリセット」操作でデータを再生成する。

## 8. 停止時間・ブロック時間

停止時間とブロック時間は、ダミーデータ本体とは分離し、Streamlit上で変更できる入力データとして扱う。

### 8.1 機械・作業者停止時間

機械または作業者ごとに、複数の停止時間を登録できるようにする。

| 対象種別 | 対象ID | 開始時刻 | 終了時刻 |
|---|---:|---:|---:|
| machine | 1 | 0 | 480 |
| worker | 2 | 120 | 180 |

既存処理の形式に合わせ、内部では以下の形式へ変換する。

```python
(resource_id, start_time, end_time, resource_type)
```

### 8.2 段取ブロック時間

全作業者に共通する段取ブロック時間として登録する。

```text
(start_time, end_time)
```

### 8.3 加工ブロック時間

全機械に共通する加工ブロック時間として登録する。

```text
(start_time, end_time)
```

初期実装では、既存処理の仕様に合わせて段取ブロックは全作業者、加工ブロックは全機械に適用する。

### 8.4 停止時間補助設定

昼休み・夜間休止の参考時間を指定日数分生成できるようにする。`horizon = 0`を9:00とし、初日の昼休みは180～240分、夜間休止は480～1440分とする。

補助設定では「稼働停止」と「段取のみ停止」をラジオボタンで一方だけ選択する。「稼働停止」は選択した機械・作業者（個別または全体）の停止時間へ追加する。「段取のみ停止」は全作業者共通の段取ブロックへ追加する。生成後は停止・ブロック設定画面で確認・修正して保存する。

## 9. 停止・ブロック時間の入力検証

保存またはスケジューリング実行時に以下を検証する。

- 対象種別が`machine`または`worker`であること
- 対象IDが存在すること
- 開始時刻が0以上であること
- 開始時刻が終了時刻より小さいこと
- スケジューリング範囲内であること
- 同一対象の停止時間が重複していないこと
- 段取ブロック時間が重複していないこと
- 加工ブロック時間が重複していないこと

不正な入力がある場合は、スケジューリングを実行せず、該当行とエラー内容を画面に表示する。

## 10. スケジューリング実行

アルゴリズムは通常探索のみとする。

画面から以下を指定できるようにする。

- 実行回数
- 使用するダミーデータ
- 停止時間・ブロック時間

実行回数分の探索を行い、各試行で同じ入力データを使用する。試行ごとに再現可能な探索用シードを使用する。

## 11. 結果表示

最低限、以下を表示する。

- 最良Makespan
- 各試行のMakespan
- 平均Makespan
- 最悪Makespan
- 実行時間
- 1回あたりの平均実行時間
- 最良試行番号
- 割当済み工程数
- 制約違反数

可視化は以下を提供する。

- 機械別ガントチャート
- 作業者別ガントチャート
- 工程ごとの開始時刻・終了時刻一覧
- 停止時間・ブロック時間の表示
- 試行ごとのMakespan比較

## 12. 制約検証

スケジュール生成後に、以下を検証する機能を追加する。

- 同一機械の処理重複
- 同一作業者の作業重複
- 工程順序違反
- リリース時刻違反
- 停止時間・ブロック時間への重複
- ホライズン超過
- 負の開始時刻
- 開始時刻が終了時刻より後になっていないこと
- 未割当工程
- 工程の重複割当

検証結果は以下の形式を基本とする。

```python
{
    "is_valid": True,
    "violation_count": 0,
    "violations": [],
}
```

```text

├── ダミーデータ確認
├── 停止・ブロック時間設定
├── スケジューリング実行
├── 評価結果
├── ガントチャート
└── 実行履歴
```

## 14. 実装順序

1. `変更版`内にStreamlitアプリの構成を作成
2. SQLiteのテーブルと接続処理を作成
3. 既存のダミーデータ生成処理を呼び出し、SQLiteへ保存
4. ダミーデータの読み取り専用表示を作成
5. 乱数シードによるリセット機能を作成
6. 製品選択方式、優先度方式、オーバーラップ切り替えを追加
7. 停止時間・ブロック時間の編集と検証を追加
8. 通常探索の実行機能を追加
9. 実行結果の保存と表示を追加
10. ガントチャートを追加
11. 制約検証を追加

## 15. 変更時の注意

- 既存の制約条件、評価方法、データ構造を無断で変更しない
- 既存アルゴリズムとStreamlit UIを分離する
- 乱数シードを固定し、同一条件で再現できるようにする
- スケジューリング実行時間を`perf_counter()`で測定する
- アルゴリズム変更、バグ修正、UI追加を同時に行わない
- 変更後は構文、実行、制約違反、結果、実行時間を確認する
